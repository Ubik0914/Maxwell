# ステータスとフロンティア

この製品の中心にある規則。ここだけは読んでおくと、あとの挙動が全部説明できる。

## 5つの状態

| 状態 | 意味 | 誰が決めるか |
| --- | --- | --- |
| **READY** | 今すぐ着手できる | 導出 or 手動 |
| **IN_PROGRESS** | 着手している | 人 |
| **DONE** | 終わった | 人 |
| **CANCELLED** | やらないことにした | 人 |
| **BLOCKED** | 待っているものがまだ終わっていない | **導出のみ** |

人が選べるのは上の4つ。**BLOCKED は選択肢に出てこない**。ブロックされているというのはグラフの形から出てくる結論であって、宣言するものではないため。あるタスクをブロックしたいなら、状態をいじるのではなく**依存を足す**。

## 何が READY を決めるか

タスクに入ってくる依存が1本もなければ READY。1本以上あるなら、**その全部の元が満たされている**ときだけ READY で、そうでなければ BLOCKED。

「満たされている」の定義:

- **START** は常に満たされている。
- それ以外のノードは **DONE のときだけ**満たされている。
- **CANCELLED は満たさない。** 誰もやらないと決めたということは、その先で必要だったものが結局作られていないということなので、後ろのタスクは待ち続ける。

タスクを DONE にすると、その下流が再計算される。直接の子だけでなく、そこから先へ連鎖する。だから1つ終わらせた瞬間に、離れたところのタスクが READY に変わることがある。

なお、人が IN_PROGRESS / DONE / CANCELLED にしたタスクは、この再計算では動かされない。導出が上書きするのは READY と BLOCKED の間だけ。

## Frontier（フロンティア）

**Frontier = READY + IN_PROGRESS**。つまり「今このストーリーで動いている仕事」。

ストーリーのヘッダーの右端に数として出ていて、1以上のときは点が生きている。ここが 0 のストーリーは、着手できる仕事が1つもない — 全部終わったか、全部が何かを待っているかのどちらか。

## ストーリーが COMPLETED になるとき

**GOAL に入ってくるものが全部 DONE か CANCELLED になったとき**、ストーリーは自動的に COMPLETED になる。

ここでだけ CANCELLED が「満たした」側に数えられる。GOAL は何も生み出さないし、何も必要としない — 「まだやることが残っているか？」という問いでしかないので、やらないと決めたものは残っていない仕事として扱ってよい。

START は満たしたことにならない。作ったばかりの（START → GOAL だけの）ストーリーが、1つも仕事をしないまま完了してしまわないため。

## ボードの BLOCKED 列

ボードのいちばん右の BLOCKED 列は片道になっている。**カードを出すことはできるが、入れることはできない。**

出せるのは、ブロックされている仕事を「やらない」と決めるのは正当な判断だから。入れられないのは、ブロックは Status Engine の結論だから — 入れたいなら、グラフで依存を足す。
