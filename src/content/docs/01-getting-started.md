# はじめに

Maxwell は、ストーリーの「始まり」と「終わり」を先に決めて、その間をタスクと依存関係で埋めていくタスク管理ツール。並んだタスクの一覧ではなく、START から GOAL へ向かう有向非巡回グラフ（DAG）としてストーリーを扱う。

そうすると「次に何ができるか」を人が管理しなくてよくなる。あるタスクが待っているものが全部終われば、そのタスクはひとりでに着手可能になり、終わっていなければブロックされたままになる。この判定は Status Engine が持っていて、手で切り替えるものではない。

## 5分でひととおり

1. **アカウントを作る** — サインアップでメールアドレスとパスワードを登録する。
2. **ワークスペースを作る** — 最初のサインイン直後はまだどこにも所属していないので、**New Workspace** から名前をつけて作る。
3. **ストーリーを作る** — **Title**、**Start State**、**Goal State** を入れる（Description は任意）。
4. **START → GOAL がつながった状態で始まる** — この一本の線が、まだ何も間に入っていないストーリー。
5. **線の上にタスクを挿す** — エッジにカーソルを合わせると「+」が出る。押すと **Insert task** が開き、START → 新しいタスク → GOAL になる。
6. **状態を動かす** — タスクを開いて Status を **In progress**、終わったら **Done** にする。そのタスクを待っていた下流のタスクは、ひとりでに **Ready** に変わる。

## 画面の見取り図

- **上の細いバー** — 左のハンバーガーがドロワー、その隣が今いるワークスペース名。
- **ドロワー** — Workspace（切り替え）、Stories（一覧・絞り込み・追加）、Settings。スマホでは画面の左端からドラッグしても開く。
- **ストーリーのヘッダー** — タイトル、状態、Done / Ready / Progress / Blocked のカウンタ、そして **Frontier**（今すぐ着手できるタスクの数）。
- **ビューのタブ** — Graph / List / Board。広い画面ではヘッダーの下、スマホでは親指の届く画面下端。

`/stories` を開くと、最後に触ったストーリーへ飛ぶ。アプリは常にどれかのストーリーを開いている状態になり、ストーリーの一覧はドロワーの中にある。

## 覚えておくと早いところ

- **Esc** はいちばん手前のものだけを閉じる。ダイアログの上にダイアログが乗っていても、1回で1枚。
- 破壊的な操作はどれも「⋮」の下にある。行の上に出しっぱなしにはなっていない。
- ワークスペースを消すと、その中のストーリー・タスク・依存・画像・他の人のアクセスまで全部消える。取り消せない。
